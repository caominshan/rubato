# Hey Tablo 移动端验收记录

## 测试范围

本轮针对 360、390、430 像素三类常见手机宽度检查首页、结果页、澄清状态、反馈重规划和错误提示。断点为 `720px`，并同时检查 `100svh`、横向溢出和 reduced-motion。

| 场景 | 验收点 | 结果 |
|---|---|---|
| 初始首页 | 标题、插画、快捷需求和输入框不横向溢出 | 通过 |
| 文本输入 | 15px 正文字号、计数器可见、Enter 行为正常 | 通过 |
| 推荐结果 | 声纹节点可点击，封面保持 16:9，标题不会撑破容器 | 通过 |
| 信息密度 | 摘要与理由限制行数，次要编辑文案在窄屏隐藏 | 通过 |
| 四种反馈 | 自动换行，按钮保持可读且禁用态明确 | 通过 |
| 加载状态 | 保留旧结果，不发生整页闪烁 | 通过 |
| 错误状态 | 错误信息具有 `role="alert"`，不会覆盖输入内容 | 通过 |
| 可访问性 | 表单有 label，结果区使用 `aria-live`，图片有 alt | 通过 |
| 动效偏好 | `prefers-reduced-motion` 下关闭关键动画 | 通过 |

## 移动端布局策略

- 页面从桌面的单屏 Grid 切换为自然文档流，避免小屏强行压缩。
- 逐集封面保持 `aspect-ratio: 16 / 9`，加载失败回退到默认播客封面。
- 声音切片详情由桌面三栏变为封面浮动 + 双列摘要，保留核心信息。
- 非核心的英文标签和第二层编辑文案在窄屏隐藏，优先保证标题、字幕、理由和反馈入口。
- 所有结果切换都发生在同一个舞台内，输入框内容不会因错误被清空。

## 已知边界

- 当前没有加入端到端浏览器自动化，移动端属于响应式样式与人工场景验收。
- 外部 YouTube 封面依赖网络；失败时会使用本地默认图。
- 低高度横屏设备不作为本轮核心使用场景，后续可增加专门的横屏断点。
